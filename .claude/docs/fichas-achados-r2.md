## Descoberta sobre a própria sentinela RULES (muda a leitura da F-06)
As frases **"maximum of 1000 expressions"** e **"evaluation error"** no `firestore-debug.log` são **diagnóstico verboso do emulador para pedidos já negados** (`DefaultEmulatorRulesAuthorizer.withVerboseErrors` reavalia a regra sem curto-circuito). Prova por bisseção, na mesma demanda real e com o mesmo PATCH: ramo A sozinho → nega sem estouro; ramo B sozinho → nega sem estouro; `A||B` → "estoura 1000". Nenhuma dessas frases aparece em pedido permitido. Em produção o resultado é só a negação.
- **F-06 reclassificada:** não há regra estourando limite em produção; o que havia era uma **escrita negada** (ver F-16).
- A sentinela passou a medir o que importa: **escritas negadas pelas rules = vermelho** (o site tentou gravar onde a regra proíbe); leituras negadas por papel = informativo.
- A "correção" de guarda `resource!=null` na regra de `demandas` (update) foi descartada: sem efeito funcional em produção, e toda publicação de rules é risco.

## F-12 — ficha de impacto (09/11/2026)
**Fato:** `castaDosClientes()` lê em `Promise.all` cinco coleções; para a Cecília as rules negam **três** delas (`contratos_cliente`, `pagamentos_mensais`, `clientes_encerrados` — todas `ae()` = gerência). Uma negação rejeita o `Promise.all` inteiro → `__cacheCasta = {}` e `__cacheCastaConfirmada = false`, a cada carga, com `console.error`.
**Quem consome:** `clientesForaDoConteudo()` ("12 telas leem desta função") e `mapaTipoCliente()` (extras). Com a casta vazia, nenhum cliente é marcado como fora do processo mensal → comportamento **permissivo** (nada some da tela da Cecília), mas a classificação mensalista/avulso/encerrado não existe para ela; onde uma tela decide algo por casta, decide "indefinido".
**Por que não é um PR pequeno:** "mensalista" nasce de `contratoAtivo` (financeiro). Sem acesso, só restam `clientes_config.tipoCliente` (marcado à mão), `clientes_extras.casta` e a lista fixa `MENSALISTAS_OPERACIONAIS_CONFIRMADOS` (19/08) — fonte incompleta e envelhecida. O invariante da casa proíbe ampliar regras financeiras para resolver tela operacional.
**Caminho recomendado:** projeção operacional mantida pelo servidor (`castas_operacionais/{slug}` = tipo + origem + atualizadoEm, escrita por Function nos gatilhos de contrato/saída/config) com leitura para toda a equipe; `castaDosClientes()` passa a ler a projeção para papéis não-gerência e as cinco coleções só para Chris/Amanda. Exige: Function nova, regra nova (leitura), migração inicial (prévia zero-write), J13 "Cecília classifica igual à Amanda". Unidade média; precisa de ok nominal (rules + Function + dado).
**Enquanto isso:** nada muda para o usuário (já é assim em produção); o `console.error` por papel pode virar `console.info` (F-03).
