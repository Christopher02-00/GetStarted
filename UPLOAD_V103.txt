O QUE DEVE DAR 404 NO SITE
---------------------------

No domínio do GitHub Pages, é correto receber 404 para:

- `AGENTS.md`;
- `firestore.rules`;
- `/scripts/*`;
- `rollback_v*/`.

O `_config.yml` exclui esses arquivos de manutenção do site público. O 404 não significa que faltaram no GitHub; confirme a presença deles pela árvore e pelo hash do repositório.

PASSO 3 — CONFERIR O SITE
--------------------------

1. Abra `https://get-started.agency/escritorio.html?v=103-financeiro`.
2. Faça uma recarga completa.
3. Entre como Chris e abra Financeiro.
4. Confirme que aparecem competência, ponte de reconciliação, carteira do mês e o bloco `Conferência dos dados reais de setembro`.

-----------------------------------

1. Em Financeiro → `Conferência dos dados reais de setembro`, clique em `Ver prévia segura`.
2. Não prossiga se aparecer qualquer texto vermelho ou `Aplicação bloqueada`.
3. A prévia correta precisa dizer que nenhuma gravação foi feita e que setembro fecha com 19 clientes ativos.

Se a prévia divergir, tire um print e pare. Não tente corrigir manualmente no Firebase e não clique outra vez para “forçar”.

ROLLBACK
--------

Se o problema ocorrer antes de qualquer correção real:

1. restaure o conjunto V102 da pasta local `rollback_v102`;
2. publique primeiro o frontend V102;
3. depois restaure as regras V102;
4. confirme novamente o build V102.

Se a correção real já tiver sido aplicada, não apague documentos, eventos, pagamentos, saídas ou contatos para voltar atrás. O rollback de código não desfaz dados e os registros V103 devem permanecer para auditoria. Qualquer reversão de dado é uma tarefa separada, com alvo e autorização específicos.
