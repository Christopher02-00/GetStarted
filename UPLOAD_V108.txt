GET STARTED — COMO PUBLICAR A V108
==================================

ESTADO DA ENTREGA
-----------------

A V108 corrige exclusivamente o pagamento da Fedalto em agosto de 2026.
Julho permanece pago em 11/08/2026. Agosto usa a data real 15/08/2026.
Setembro permanece cortesia exata e o contrato continua ativo depois disso.

Esta pasta é uma entrega local. Nada foi publicado automaticamente no GitHub
ou no Firebase e nenhuma correção foi aplicada aos dados reais.

BUILD ESPERADO
--------------

2026-08-23-pagamento-fedalto-agosto-v108

ARQUIVOS DO PACOTE
------------------

A lista autoritativa será MANIFESTO_SHA256_V108.txt. Preserve caminhos e
nomes exatamente como aparecem nele.

O pacote curado contém:

- arquivos não-rollback para o GitHub;
- MANIFESTO_SHA256_V108.txt;
- rollback_v107 apenas como reserva local;
- os testes V108 de núcleo e interface;
- nenhum node_modules, log, captura, memória privada ou metadado macOS.

GITHUB
------

1. Abrir a pasta ATUALIZACAO_ATUAL_V108.
2. Usar MANIFESTO_SHA256_V108.txt como lista autoritativa.
3. Enviar todos os arquivos do manifesto, exceto os sete de rollback_v107.
4. Enviar também o próprio MANIFESTO_SHA256_V108.txt.
5. Preservar a estrutura scripts/ e os demais caminhos relativos.
6. Não enviar rollback_v107, o ZIP, memória privada, node_modules, logs ou
   capturas de tela.
7. Excluir do GitHub as duas cópias antigas da raiz, se ainda existirem:
   regression-critical.mjs e regression-v85-acesso-calendarios-clientes.mjs.
   As suítes oficiais permanecem somente dentro de scripts/.
8. Fazer o commit e aguardar o GitHub Pages.
9. Recarregar sem cache e confirmar o build V108 antes de abrir a correção.

FIREBASE — OBRIGATÓRIO ANTES DO CLIQUE
-------------------------------------

A V108 altera firestore.rules. O usuário DEVE publicar o firestore.rules da
V108 no Firebase antes de clicar em “Aplicar correção”.

Não reutilizar regras V107 e não ampliar permissões manualmente. Se o
frontend V108 entrar no ar antes das regras, a aplicação deve permanecer
bloqueada com permission-denied; isso é proteção, não motivo para contornar
as regras.

ROLLBACK
--------

rollback_v107 guarda os sete arquivos operacionais exatos da V107 e não deve
ser enviado ao GitHub. Antes do clique real, ele permite restaurar frontend e
regras. Depois da aplicação real, rollback de código não apaga recibo nem
desfaz pagamento; reversão de dados exige outra operação auditada.

PARAR E REGISTRAR
-----------------

Pare sem clicar e registre a mensagem completa se aparecer cliente errado,
competência diferente, data diferente de 15/08/2026, contrato encerrado,
drift, permission-denied depois da publicação das regras, timeout, cota ou
estado indisponível.
